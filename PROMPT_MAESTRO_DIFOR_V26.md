# PROMPT MAESTRO — DIFOR V26 SALES WORKSPACE

Trabaja siempre sobre el código completo actual de DIFOR. No reconstruyas desde cero y no entregues parches. Conserva datos, PWA, GitHub/Cloudflare, módulos y compatibilidad existentes.

## Objetivo
Convertir DIFOR en una herramienta de venta automotriz multimarca que reduzca scroll, mejore jerarquía visual y guíe el trabajo comercial diario hasta lograr visita, negociación o venta.

## 1. INICIO — NO CAMBIAR SU FUNCIÓN
Inicio es una pantalla comercial para usar frente al cliente. No mostrar información interna, KPI, prospectos, ventas, BK, metas, recordatorios ni datos personales de gestión. Mantener accesos de marca y recorrido Marca → Modelo → Versión → página oficial / ficha técnica / información comercial. La base visual sigue siendo DIFOR.

## 2. BLACK / WHITE EXECUTIVE
No llenar toda la interfaz del color del tema. Usar fondos neutrales, superficies claras/oscuras discretas y color de acento sólo para selección, acciones y alertas. El texto y los datos deben dominar visualmente. Reducir glow, gradientes, bordes repetidos y tarjetas innecesarias. Diseñar para reconocer información en segundos.

## 3. MENOS SCROLL
Priorizar layouts horizontales en PC/tablet, controles compactos, cabeceras pequeñas, tablas compactas, pestañas y contenido progresivo. Una pantalla operativa principal debe intentar resolverse en 1–1,5 alturas de viewport. En móvil conservar claridad sin scroll horizontal accidental.

## 4. SALA DE VENTA = SHOWROOM
Presentar vehículos como afiches comerciales diferenciados por marca/modelo/versión. Mantener identidad DIFOR como base y usar acentos secundarios por marca sin convertir el sistema en cinco webs distintas. Cada afiche debe priorizar imagen, modelo, versión, atributos clave, precio y acciones Web / Ficha / Cotizar / Comparar.

## 5. PROSPECTOS CRM
Prospectos debe ser un módulo principal y privado. Flujo: Ingreso → Contacto → BK → Propuesta → Visita → Negociación → Venta. Si no se concreta, mover a Seguimiento futuro con motivo y próxima fecha. Nunca borrar la historia comercial.

Cada prospecto debe mostrar: procedencia, vehículo(s), etapa, score de oportunidad, próxima acción, fecha, BK, cotización, llamada, WhatsApp, publicidad, visita y venta. Regla: Prospectos activos sin próxima acción = 0.

## 6. METODOLOGÍA DE TRABAJO
Al crear un prospecto: registrar procedencia y vehículo; enviar WhatsApp informativo; llamar; evaluar siempre en BK; comunicar preaprobación/aprobación cuando corresponda; cotizar; enviar publicidad relevante; concretar visita o venta; si no se logra, respaldar para futuro.

## 7. SCORE Y CONTROL
Crear score de oportunidad basado en acciones reales. Priorizar pendientes vencidos, prospectos con BK favorable, cotización enviada y visita pendiente. Dashboard CRM debe medir no sólo cantidades sino avance: contactados/prospectos, BK/prospectos, cotizados/prospectos, visitas/prospectos, ventas/prospectos.

## 8. ASISTENTE MULTIMARCA
Agregar herramienta privada fuera de Inicio para responder “¿qué vehículo de mis marcas calza mejor?”. Filtrar por uso, presupuesto, transmisión, combustible, tracción, pasajeros y prioridades. Recomendar sólo vehículos cuya información esté cargada en DIFOR; nunca inventar especificaciones.

## 9. CONTEXTO
Inicio vende el vehículo. Prospectos ayuda a venderle al cliente. Dashboard ayuda al ejecutivo a mejorar su gestión.

## 10. ENTREGA
Entregar siempre ZIP completo, nunca snippets/parches. Actualizar versión, cache, manifest y README. Validar sintaxis JS, service worker, worker Cloudflare, integridad ZIP, responsive PC/tablet/móvil y compatibilidad de datos existentes.
